# Phase 8: images in questions and options (decided 2026-11-04, step 1 coded)

Asked by the user on 2026-11-04: a question can be an image (a figure, a pattern, a chart), and its options can be images. Extends `phase-6-assessments.md` (tests, sections, questions, attempts). Needed for matrices and figural reasoning, spatial and rotation items, and chart or table questions of skill tests. Step 1 (the API) is coded (last section); steps 2 to 4 wait. Decided by the user on 2026-11-04: images on choice, number, text and drawing questions (D2); **several images per question** (D1); 2 MB, JPEG, PNG or WebP, 1600 pixels (D5); **alternative text required** (D4). D11 is parked, D12 was decided by the user on 2026-11-04 (with G5: the server lays the strokes over the sheet); the others (D3, D6 to D10) are this design's and were coded as written in step 1.

**Read from the code (2026-11-04):** `assessment_questions` has `text` and no image column; `assessment_question_options` has `label` (500 characters) and no image column; the only image in the module is the candidate's own **drawing** answer (`UploadDrawing`: `ImageProcessor` re-encodes it, the file sits on the private disk, an endpoint hands it to the reviewer). Options have **no id**: `UpdateQuestion` deletes and re-inserts them on every save and the answer keeps their positions. A test that was sent to a candidate is locked (`AuthoringAccess::author`, 409 `test-locked`); `CloneTest` copies sections, questions, norms and templates into a new draft. A candidate reads a question only when `AttemptQuestions::reachable` allows it (the section navigation rule).

**Example from the user (2026-11-04, a printed figural test, items 5 to 9):** every item says "Pilihlah salah satu gambar yang berbeda dari gambar lain!" (choose the picture that differs from the others) and shows **five pictures labelled A to E in one row** (letters, rotated arrows, dot patterns, boxes with shapes, line figures). So the common case is **no image in the question, one image per option**, the instruction repeated in the text, five options side by side with the letter under each; the picture itself is the content and a description of it would give the answer away (see D4). The same pattern also fits matrices and rotation items.

**Second example from the user (2026-11-04):** one picture holding **eight line drawings in two rows of four** (a flower, a bird, a mosque, a phone, a syringe, a camera, fruit, a mushroom), the kind of sheet a candidate looks at for a limited time and is then asked about (a picture-memory test). It adds a need the first example does not have: an image that is **shown for a limited time and then hidden**, with questions that come after and must be answered without seeing it. **Reading corrected 2026-11-04:** the black frame with eight white squares in two rows of four is a **Wartegg** sheet filled in by a candidate (confirmed by the user 2026-11-04), not a memory test. So the need is a **drawing question whose canvas starts from a printed sheet** (D12), and D11 is parked until a real timed-stimulus example exists.

## Decisions

- **D1 (decided): the question has up to 4 images (a limit of the design, `assessment.max_question_images`, default 4, range 1 to 8), and every option may have one.** The images sit above the text in their order; the text stays required (for a pure figure question it can be a short instruction such as "Choose the piece that completes the pattern"). An option always keeps its label (for a picture option the letter, A to E, shown under it) and may add a picture; Likert, forced choice and most/least keep text only (D9).
- **D2 (decided): types.** Images are allowed on `single_choice`, `multiple_response`, `true_false` (question image only), `number`, `short_text` and `long_text` (question image only), in skill tests and in psychological batteries alike. `likert`, `forced_choice` and `most_least` (statements) and `video_answer` take no image; `drawing` takes the question image as its sheet (D12).
- **D3: upload, then reference.** (A question's own images are a list, `image_ids`, in the order shown.) Options have no id and are replaced on every save, so an image is uploaded first and the question is saved with the image's id. `POST` the file to the test (`assessment_question_images`, with the test id, not yet attached); the question `PUT` names `image_ids` for the question and `image_id` per option. A save that names an image of another test is 422 `invalid-image`. An image no question names is an orphan and is purged after 24 hours.
- **D4 (decided): alternative text is required.** Every image has `alt` (1 to 300 characters), required with the upload, so a screen reader says what is shown. For an odd-one-out or matrix item a description would give the answer away, so the editor tells the author to write a neutral text ("Figure A of five", "Sheet with eight squares") and the runner reads it as written.
- **D5 (decided): size and format.** JPEG, PNG or WebP in, checked by content and re-encoded by `ImageProcessor` (metadata dropped), shrunk to fit 1600 by 1600 pixels, never enlarged; at most `assessment.max_question_image_megabytes` (setting, default 2, range 1 to 5) before processing.
- **D6: the file is content, not personal data.** It stays with the test: not touched by assessment erasure or the raw data archive (they hold answers, not questions). It is deleted with its question, option, replacement or test (`DeleteQuestion`, `DeleteTest`, a save that no longer names it). **`CloneTest` copies the files** (a new path per copy), so deleting one test never breaks the other.
- **D7: delivery to the candidate.** One route for the question's pictures and the options' pictures alike, `GET me/assessment/invitations/{id}/attempt/questions/{questionId}/images/{imageId}` (an option's picture belongs to its question, so its id is enough), under the same gate as the question itself (`reachable`: the candidate is signed in, the attempt is open, the section lets them see the question). It is a read: it does not extend the idle timer and does not ask for the attempt session header, because an `<img>` cannot send it. Headers: `Cache-Control: private, max-age=600`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'`. A screenshot cannot be prevented; the integrity log already records focus changes.
- **D8: delivery to authors and reviewers.** The author previews the images through `GET` routes of the authoring API (the test's author, as for the questions); the reviewer in Portal Mitra and a company member who sees the answers read them through the question's review view, the same way. The PDF report never shows questions, so it is unchanged.
- **D9: scored statements stay text.** For Likert, forced choice and most/least the statement is the item and its wording is validated and normed; images would change what is measured. They are refused (422 `invalid-question`).
- **D11 (parked 2026-11-04, no confirmed example): a `stimulus` question for a timed picture.** A new question type `stimulus` (skill tests and psychological batteries): text (the instruction, "Remember the pictures; you have 30 seconds"), one image, `display_seconds` (5 to 300), no answer and no points. The runner shows it, counts the seconds down and moves on by itself; the candidate may move on earlier but **never come back**. The section must be one that does not let the candidate go back (the existing navigation rule; a section with a stimulus cannot allow it, 422 `invalid-question`). The server enforces the window, not the browser: the first delivery of the image of a stimulus records the time in the attempt (`assessment_attempt_questions.first_shown_at`), and the image endpoint answers 410 `stimulus-expired` after `display_seconds` plus 3 seconds of grace, so reloading or calling the URL later shows nothing. The questions that follow are ordinary ones (options as text or as images, a number, a short text, e.g. "How many drawings were in the second row?", "Which of these was shown?"); they carry no image of the stimulus. The timer of the section runs through the stimulus.
- **D12 (decided 2026-11-04; the need is the Wartegg sheet): a drawing question may carry an image as its sheet.** A `drawing` question takes **exactly one** image (D1's list is one long) as the **background of the canvas** (the candidate draws on it, for example the eight squares with their printed marks of a Wartegg sheet; the image is part of the screen, not of the stored drawing) and shows it as the reference when the candidate uploads a photo instead. **Decided 2026-11-04 (G5): the server flattens, not the browser.** The runner sends only the candidate's strokes (a transparent PNG the size of the sheet); the server keeps them as they are and, when a reviewer reads the drawing, lays them over the question's own sheet, so the sheet is always the one of the question and cannot be swapped by the browser. A photo the candidate uploads instead is kept as it is (it already shows the paper sheet) and is not laid over anything. Type rule: `drawing` is allowed to carry the question image (D2 changes accordingly).
- **D10: no new permission and no switch.** Whoever may edit a test may attach images; a locked or archived test refuses them like any change (409 `test-locked`, `test-archived`).

## Schema

One migration. A table `assessment_question_images`: `id`, `test_id` (cascade on delete), `question_id` (null until a save names it; cascade on delete), `option_position` (null for the question's own images, the option's position otherwise), `position` (the order among the question's own images, 0 for an option's), `path`, `content_type`, `size_bytes`, `width`, `height`, `alt` (300), timestamps; unique on (`question_id`, coalesce(`option_position`, 0), `position`) for attached rows (0 is free because option positions start at 1). Because the question save replaces its options and the images name their position, `UpdateQuestion` rewrites `question_id` and `option_position` of the images it names in the same transaction and detaches (then deletes the file of) those it no longer names.

## API

- `POST company/assessment/tests/{id}/images` (multipart `file`, `alt`) and the same under the provider's and the admin library's test routes: the author of the test; answer `{id, alt, width, height}`. Errors: 422 `invalid-image`, 413/422 `file-too-large` (reuse), 409 `test-locked` or `test-archived`.
- The question body (create and update) gains `image_ids` (a list, at most `assessment.max_question_images`; 422 `too-many-images` beyond it) and `options[].image_id` (nullable); the question resource gains `images[]` (`{id, alt, width, height}`; the picture is read from `GET tests/{id}/images/{imageId}`, the storage path is never sent) and `options[].image`. Types that take no image (D2, D9) answer 422 `invalid-question` with the field; an option's picture on any type but single or multiple choice is 422.
- The attempt's question view carries `images[]` and `options[].image` with the delivery URLs of D7, never the storage path.
- `assessment:purge-question-images` (daily, 04:05): unattached images older than 24 hours, file and row.
- Messages: `invalid-image` exists (it also covers a missing or too long `alt`); `too-many-images` is new. An option always has its label (D1), so there is no "label or image" rule.

## Screens

- **Question dialog (Portal Mitra, Console library, and every editor that uses the shared question dialog; to verify at coding which editors share it):** an image box for the question (choose, replace, remove, alt text field, thumbnail) and one per option; the existing "save whole" flow is unchanged, the upload happens when the file is chosen. Validation of type and size before sending, with the same messages as the API.
- **Career runner:** the question images above the text, in order (alt text read by assistive tech, a "view larger" dialog each); options as a row or grid of images (five in a row on a wide screen as in the example, fewer columns on a phone) with the label or letter under each, selectable like text options; keyboard and screen-reader labels per option. Images preload for the question in view and the next one.
- **Review and result views** (Portal Mitra, Workspace): the question shows its image like the runner.
- **Demo data:** one skill test question with a generated simple figure (an SVG-free PNG drawn by GD in the seeder) so the whole path can be tried.

## Steps

1b. Parked with D11: the `stimulus` type, `first_shown_at`, the expiry of the image, the section rule.

4. Review and result views, demo data, docs.

## Left out

Images inside an option's explanation; image in the candidate's free-text answer; an image library shared between tests (copy by upload); zoom and pan tools in the runner beyond "view larger". A picture shown for a limited time is not left out but parked (D11).

## Coded: step 1, the API (2026-11-04)

Migration `000409` (`assessment_question_images`), `QuestionImage` and `QuestionImageRepository` (the pictures of a question hang on `Question::$images` and `QuestionOption::$image`, read with the question), `QuestionImageRules` (types, one sheet for a drawing, the limit), `QuestionImages::place` (names the pictures in the transaction of the question save; what is no longer named is deleted, the file after the commit), `UploadQuestionImage` and `GetQuestionImage` (`POST` and `GET tests/{id}/images[/{imageId}]` for the company, provider and library authors), `GetAttemptQuestionImage` (`GET me/assessment/invitations/{id}/attempt/questions/{questionId}/images/{imageId}`: only a question the section lets the candidate see now, a read that needs no session header because an `<img>` cannot send it), `PurgeOrphanQuestionImages` (`assessment:purge-question-images`, daily 04:05), delete of a question, section and test delete the files, `CloneTest` copies the files. Settings `assessment.max_question_images` (4) and `assessment.max_question_image_megabytes` (2). New error code `too-many-images`; `invalid-image` also covers a missing or too long `alt`. Not done yet: the review views of the provider and the company (D8), the screens (steps 2 to 4), the canvas sheet of a drawing (D12: the API accepts one picture on a drawing question, the runner does not draw it yet).

## Open (gap analysis 2026-11-04)

Found after step 1, not decided yet; each is for the user to settle before the step named.

- **G1 Practice questions (before step 3):** `PracticeResource` (`GET me/assessment/invitations/{id}/practice`) sends labels only, and the image route opens only while the attempt is open. A figural test needs its pictures in the examples most of all: practice needs `images[]` and `options[].image` and a read route under the practice gate.
- **G2 Catalog samples (before step 4):** `CatalogEntryResource.samples` (the company previews a battery) sends the text and the labels only; no route lets the company read a sample's picture.
- **G3 Manual scoring (before step 4):** `ScoringItemResource` sends the question as text; an assessor who scores a short or long text answer to a question with a picture does not see the picture. D8 names "the review view" in general; the scoring queue is one of the views it must cover.
- **G4 Alt text of options (step 2):** the `alt` reaches the candidate in the JSON, so a describing text gives the answer away to anyone reading the response. Proposed: the editor fills "Gambar pilihan A" by default and warns when the author changes it.
- **G5 The Wartegg sheet: decided 2026-11-04, the server flattens** (see D12). Coding it touches the API too: the drawing read lays the strokes over the sheet (a canvas drawing only, not an uploaded photo), which the answer already records (`Drawing::$source`, `DrawingSource`). To check when coding: `ImageProcessor` must keep the transparency of the strokes PNG when it encodes it again.
